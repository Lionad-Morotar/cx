# cx-agent-manual 创作手册

四阶段(取材 → 组织 → 落笔 → 验收)的细则依据。目标产物:给 agent 看的业务页面操作手册(SKILL.md),agent 用它生成展示用 cx 组件,或经 API 操作页面。

## 取材(阶段 1)

事实源三类,逐类取证,禁止二手转述:

- 页面组件:入口页(`pages/.../index.vue`)的模板结构、页面级状态(共享查询条件、选中协议、显隐时机)、页面级行为(导出、跳转)。页面级编排是「不属于任何单一物料」的行为,在操作树里作为根级节点出现
- cx 物料:每个物料的 props(名字、类型、默认值、变体分支)、emits(事件名与载荷)、插槽、变体形态(level/type/状态驱动的外观分支)。物料是 agent 生成展示组件的最小单位,prop 即变体组织方式
- service 层:页面及其物料消费的接口,URL 逐条从 service 源码提取(注意个别调用缺前导斜杠、query/body 形态、环境注入字段);更重要的是物料内的真实组参处——请求体如何拼、字段如何改写(如小区域档按全国口径)、过滤值如何拼接(`;` 分隔、级联取末级),这是覆盖 openapi 定义的取证来源
- openapi 参考文档:若有后端接口文档仓,以 `ignore = all` 子仓挂在项目 packages/ 下仅作参考(防版本绑定);它提供 operation 全集与骨架,但其请求/响应定义常孱弱不可靠(类型残缺、语义缺失),只作覆盖的底本,不作交付内容

取证清单(逐项与源码核对,不许从拆解文档搬):

- 入口路由与进入方式(导航是服务端下发还是硬编码,布局容器形态)
- 全部按钮与图例的用户可见文案(逐字)
- 控件交互规则(锁定拦截、互斥清空、显隐条件、防抖时长)
- 列表分页与空态规则(每页条数、空判定、页码器形态)
- 跳转出参(目标页面与 URL 形态,只提及不展开)
- 每个接口的真实传参:消费侧组参代码逐字段读(chainObj 展开、regionType 改写分支、分页与过滤字段、环境注入字段)

反例(取自真实弯路):「带返回按钮」「每页条数可选 10/15/20」这两条曾从拆解文档转述入手册,源码核对后均不成立——前者是布局样式分支,后者是组件死属性。凡写入手册的事实必须能指出源码位置。

## 组织(阶段 2)

操作树的折叠判据:

- 一个操作 = 用户意图层面上的一件事(查看产业链条、浏览投资机构)。同一面板里的「筛选」「点卡片」「关注」是该操作的子步骤,不是并列操作
- 子步骤展开顺序按用户动线:先进入/切换,再筛选/浏览,再交互/跳转
- 页面级编排(共享查询条件、选中协议、导出)挂在离它最近的操作下,或作为操作的前置规则行(「再次点击同一节点取消选中」)

组件挂载规则(组件挂进子步骤,不单列):

- 只写 prop 的业务语义:`prop showActions: true 时显示关注/触达按钮组`——不写 prop 类型、不写默认值(除非默认值即行为)、不写样式数值
- 变体形态用枚举值表达:`level: 2 卡片容器 / 3 带子级列表 / 4 叶子`——这是 agent 生成展示组件时需要的分支信息
- 只读的展示物料(图例、装饰)一句带过,不写 prop

接口挂载规则(接口挂进数据点):

- 形态:`GET /service-admin/xxx/yyy`——功能一句简述,路径包 code 并链接到 references 内嵌文档:[`/service-admin/xxx/yyy`](references/reqs/xxx/yyy.md)
- 手册正文只写语义:「按链节点 id 查 AI 分析;未选中节点时先把产业链换算为链根节点再查」;逐字段的请求/响应用法交给内嵌接口文档
- 条件改写规则(如某档按全国口径请求)必须写,这是 agent 复现 API 调用的关键行为
- 远程配置 JSON 等非后端 API 照写,标注「非后端 API」

## 落笔(阶段 3)

章节骨架(顺序即重要度):

1. 这是什么:一段话产品定位(是什么、为谁、回答什么问题,约 200 字,可融入进入方式一句)+ 关键术语列表(全文复用的词都收进来)。布局形态、共享条件机制、路由细节不是「这是什么」——共享条件机制挪操作树开头段,布局细节挂进对应操作
2. 上下文:元描述集中段(操作树之前)——后端 baseURL 环境变量、URL 前缀、鉴权头、环境判定(如 `import.meta.env.MODE` 严格等于 `'test'` 为测试环境)等技术约定统一在此交代;操作树正文与接口行保持业务语言,不夹这些源码机制描述
3. 操作树:核心章,嵌套列表组织;开头段交代共享查询条件机制与接口文档指引
4. 资源清单:文档来源说明一句(openapi 底本 + 真实调用取证覆盖)+ 接口文档分组链接(references/reqs/)。接口清单不单立章——接口的完整信息在 references 文档里,清单即链接目录

硬规则:

- 全文嵌套列表,禁用 Markdown 表格(参数、对比、术语、路由一律列表)
- 业务语言自含:禁位置代号(tab1/tab3),禁未立框架的裸路径(先说产品和入口,路径只作技术锚点附注)
- 每个功能点描述约 100 字内,写现状(现在时),不写 Why 与开发历史
- 禁写:data-testid、svc 函数名、rem/px/hex 样式数值、文件路径(references 相对链接除外)
- SKILL.md 不引用外部 API 技能(如 86links-api):接口知识必须内嵌 references 自足,agent 不应被要求去别处查
- 触发词写在 frontmatter description,来自用户实际表达,不虚构

接口文档内嵌(references/reqs/,以 URL path 去重):

- 每个接口一篇:`references/reqs/<path>.md`(path 为去掉服务前缀的 URL 路径,如 `industryInsight/chainCompany/list.md`);远程配置 JSON 等非后端 API 单独成文并标注
- 体例:标题为 `方法 完整路径`;功能一句;「请求」节按标准模板逐字段入列(query/body 形态、业务语义、枚举取值、拼接规则、本接口的改写规则、分页、互斥、防抖);「响应」节列消费侧真实用到的字段语义(混型、空态、单位口径);文末「来源」标注 openapi operation 名与「经页面真实调用取证覆盖」
- 标准模板:多接口共享的查询结构(如 chainObj)在每篇请求节完整重列,字段顺序与措辞各篇对齐——允许跨文档重复,渐进式披露让每篇自足;禁止抽成「共享数据结构」独立文档让 agent 跳读
- 覆盖纪律:openapi 底本的骨架可留,但请求/响应定义必须由源码组参处覆盖;底本有而页面不用的参数,标注「本页面不使用」而不是照抄
- 泛型样板(200/401/403 状态码表、鉴权 scheme)无业务价值,不进文档——统一约定已在上下文段交代

响应侧专用结构:

- 只在某接口响应出现的结构(如链节点树项)并入该接口文档的响应节,不单独成文

## 验收(阶段 4)

对账脚本断言五类(参照实现:shushi.86links.com 的 verify-skill-doc.mjs):

- 存在性:手册里每个 cx 组件名能映射到 components/cx/<kebab>/src/index.vue;references 文档逐个存在(接口文档、共享结构);SKILL.md 中全部 references 相对链接有效
- 一致性:接口 URL 与 service 源码双向核对(文档有的源码必有,页面消费的清单必全);注意去前导斜杠后按子串对账
- 覆盖标记:每篇接口文档含「真实调用取证覆盖」标注;消费共享结构的接口文档各自完整入列共享字段(chainCode/regionType 等),且不链任何共享结构文档
- 元描述归位:环境判定、baseURL、鉴权头只出现在「上下文:」段,操作树正文不含(如断言正文无 `import.meta.env.MODE`)
- 禁用项:无 data-testid、无 svc 函数名(先剥离 URL 与 references 链接路径再查,否则链接里的同名文件误报)、无 rem/px/hex、无 Markdown 表格、无位置代号、不引用外部 API 技能
- 结构:必有章节齐全(这是什么/操作树/资源清单),必无章节不出现(需求树/设计取舍/维护注记/接口清单),「这是什么」为单段扩写,操作数与子步骤嵌套密度达标
- frontmatter:name/description/metadata.version 齐全,description 含 Use when

脚本放运行目录(如 flow-dev run-dir),不随手册提交;如项目要求可提升为技能内 scripts/ 长期值守。

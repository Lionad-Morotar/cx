# cx-agent-manual:业务页面 → agent 操作手册

把 cx 组件体系驱动的业务页面转换为 agent 可消费的领域技能文档(SKILL.md)。消费手册的 agent 有两种用法:生成展示用 cx 组件(向最终用户展示页面能力),或经 API 操作页面(按接口复现用户行为)。

## 硬事实

- 受众是零上下文 agent:它不认识产品、页面路径与实现黑话,手册必须业务语言自含
- 组织骨架是操作树,不是组件清单:cx 组件与接口挂在它们真正服务的操作步骤下,agent 按「我要做 X」取用,不是按「有什么零件」拼装
- 手册不写源码标识与测试锚点:svc 函数名、data-testid、文件路径对生成与 API 操作都无价值
- 接口文档内嵌自足,不外挂 API 技能引用:用到的接口按 URL path 去重落到 `references/reqs/<path>`;openapi 生成文档常孱弱不可靠,必须用源码真实业务传参(组参处取证)覆盖后再交付
- 共享结构不单独成文:多接口共享的查询结构(如 chainObj)按标准模板在每篇接口文档的请求节就地完整入列——允许跨文档重复,渐进式披露让每篇自足;「共享数据结构」式抽离对 agent 是跳转负担
- 「这是什么」只写产品定位:一段话讲清产品是什么、为谁、回答什么问题;布局、进入方式、共享条件等机制性内容不属于它,挪去操作树开头段或对应操作
- 元描述集中收进「上下文:」段:环境判定(`import.meta.env.MODE`)、baseURL、鉴权头等技术约定统一交代在操作树之前的上下文段;操作树正文与接口行保持业务语言,不夹源码机制描述

## 流程四阶段

按阶段读取对应 reference,不要初始化时一口气全读。

### 1. 取材扫描

目标:拿到页面全部事实源,不留二手转述。

- 入口页面组件 + 它消费的 cx 物料(props/emits/变体分支)+ service 层 URL + 物料内真实组参处(请求体如何拼、字段如何改写)+ 布局/导航事实
- 事实必须与源码对账:入口路由、导航来源、按钮/图例文案、接口路径与组参,逐条取证,禁止从既有拆解文档转述(拆解文档的目标是「待做」,手册的目标是「现状」)
- 判据与取证清单见 [references/authoring.md](./references/authoring.md)「取材」节

### 2. 组织操作树

目标:把功能点折叠成以用户操作为轴的树。

- 操作 = 用户能做的一件事(查看 X / 筛选 X / 下载 X);子步骤 = 完成该操作的分支与规则
- cx 组件挂进子步骤:写什么 prop、取值、对业务的作用(变体形态),不写样式数值
- 接口挂进数据点:完整路径 + 功能简述,并链接到 references 内嵌接口文档
- 组织判据、组件挂载规则、接口落位规则见 [references/authoring.md](./references/authoring.md)「组织」节

### 3. 落笔与接口文档内嵌

目标:写成手册正文,接口文档与共享结构落 references。

- 章节:这是什么 → 上下文(元描述)→ 操作树 → 资源清单(接口清单不单立章,并入资源清单);术语表收在「这是什么」
- 接口文档:以 URL path 去重落 `references/reqs/<path>.md`,请求/响应的业务用法用源码组参处的真实传参覆盖 openapi 定义,文末标注来源 operation 与「经真实调用取证覆盖」;远程配置 JSON 等非后端 API 同样成文并标注
- 共享查询结构:不单独成文,按标准模板在每篇接口文档请求节就地完整入列(字段语义、枚举取值、拼接规则、本接口的改写规则)
- 全文嵌套列表,禁用 Markdown 表格;章节、语言、列表形态的硬规则见 [references/authoring.md](./references/authoring.md)「落笔」节
- frontmatter 按 cx 技能约定:name/description/metadata.version,第三人称 description 带 Use when 触发词

### 4. 对账验收

目标:手册里每个事实都能被证伪且证伪通过。

- 用对账脚本断言:cx 组件名存在、接口 URL 与 service 层一致、references 文档齐全且含覆盖标记、共享字段就地入列、元描述归位于上下文段、SKILL.md 不引用外部 API 技能、无禁用内容(data-testid/svc 函数名/样式数值/表格/位置代号)、操作树嵌套充分
- 参照实现:shushi.86links.com `~/.flow-dev/runs/260808-industry-insights-skill/verify-skill-doc.mjs`(145 断言);本技能的产物验收判据见 [references/authoring.md](./references/authoring.md)「验收」节

## 红线

- 不从既有需求拆解文档转述内容:拆解文档记录「要做什么」,手册只写「现状是什么」,两者来源独立取证
- 禁止把组件/接口平铺罗列成两章:操作树是唯一骨架,平铺对零上下文 agent 不可读
- 禁止在手册出现 data-testid、svc 函数名、rem/px/hex 样式数值、Markdown 表格
- 禁止照抄 openapi 生成文档交付:它的请求/响应定义必须由源码真实组参覆盖,覆盖不到的参数标注「本页面不使用」
- 禁止把共享查询结构抽成独立文档:抽离迫使 agent 反复跳读,标准模板就地入列的重复是可接受的自足成本
- 触发词不许虚构:description 的触发话语来自用户实际表达或约定俗成
